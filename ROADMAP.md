# Roadmap

This roadmap describes intended maintenance direction, not guaranteed delivery dates.

## Near term

- Keep repository-wide validation green.
- Establish issue and pull-request triage conventions.
- Add real versioned GitHub releases for mature tools.
- Expand per-tool tests around parsing, planning, report generation, and safe file operations.
- Improve dependency documentation and reproducible setup.
- Continue improving beginner-oriented quick starts and annotated guides.
- Add release smoke-test checklists for Windows-specific tools.

## Medium term

- Standardize common logging/report conventions where useful.
- Add reusable safe-file-operation helpers for tools that review/move/delete files.
- Add more fixture-based tests for duplicate detection and archive handling.
- Improve configuration validation and actionable error messages.
- Document compatibility matrices for important external dependencies.
- Add contribution examples for first-time contributors.

## Community and ecosystem goals

- Earn adoption through useful releases rather than manufactured activity.
- Use issues and pull requests as the public maintenance record.
- Track real user-reported bugs and compatibility cases.
- Welcome external contributors and credit substantive contributions.
- Keep the repository small enough that each included tool receives active maintenance.

## Not planned

- Artificial stars, forks, downloads, issues, or other engagement.
- Bundling private credentials or session files.
- Automatic destructive behavior merely to reduce confirmation steps.
- Copying third-party projects without honoring licenses and attribution.
