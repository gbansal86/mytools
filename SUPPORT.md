# Support

Start with the README inside the affected tool folder and its troubleshooting/quick-start documentation.

When reporting a problem, include the tool name, Windows version, relevant dependency versions, exact launcher/command used, exact error text, expected behavior, actual behavior, and a minimal reproduction using non-sensitive sample data.

Do not post API keys, tokens, Telegram sessions, private media, personal diagnostic data, or other secrets.

Use a **bug report** when documented behavior is failing reproducibly. For sensitive vulnerability details, follow [SECURITY.md](./SECURITY.md).

Support is best-effort. Hardware-specific Windows behavior, third-party service outages, antivirus policies, corporate endpoint controls, and external dependencies may be outside the maintainer's control.
